可以，按“**要记录什么 → 在哪里看 → 怎么拿到**”给你。

课件实验一要求分析 ARP、DNS、TCP、HTTP、HTTPS，并解释下载 UCAS 页面的整个过程。

- **h1 的 IP 地址 / MAC 地址**
  在 Mininet 里：

  ```
  mininet> h1 ip addr
  ```

  找 `h1-eth0`：

  ```
  link/ether xx:xx:xx:xx:xx:xx   ← MAC
  inet 10.0.0.1/8                ← IP
  ```

- **默认网关 IP**  

  ```
  mininet> h1 ip route
  ```

  找：

  ```
  default via 10.0.0.3 dev h1-eth0
  ```

  这里 `10.0.0.3` 就是默认网关。

- **DNS 服务器 IP**
  你手动设置的是：

  ```
  cat /etc/resolv.conf
  ```

  看到：

  ```
  nameserver 8.8.8.8
  ```

  所以 DNS Server 就是 `8.8.8.8`。课件也是这样配置的。

- **`www.ucas.ac.cn` 解析得到的 IP**
  最推荐直接从 Wireshark 的 DNS Response 里看。过滤：

  ```
  dns
  ```

  点开 `Standard query response`，展开：

  ```
  Domain Name System
  → Answers
  ```

  看里面的：

  ```
  A xxx.xxx.xxx.xxx
  ```

  这个就是 IPv4 地址。也可以在命令行辅助看：

  ```
  nslookup www.ucas.ac.cn
  ```

- **ARP 查询了谁、返回什么 MAC**
  Wireshark 过滤：

  ```
  arp
  ```

  你通常会看到：

  ```
  Who has 10.0.0.3? Tell 10.0.0.1
  10.0.0.3 is at xx:xx:xx:xx:xx:xx
  ```

  记录：

  ```
  请求方 IP
  目标 IP
  返回的 MAC
  ```

  课件对 ARP 的定义就是“IP 地址 → 下一跳 MAC 地址”。

- **DNS Query / Response**
  过滤：

  ```
  dns
  ```

  找成对的：

  ```
  Standard query A www.ucas.ac.cn
  Standard query response A ...
  ```

  点开后记录：

  ```
  查询域名
  查询类型 A / AAAA
  DNS服务器IP
  返回IP
  是否有CNAME
  ```

- **TCP 三次握手**
  先过滤：

  ```
  tcp.flags.syn == 1
  ```

  找到：

  ```
  SYN
  SYN, ACK
  ```

  然后点其中一个包，看：

  ```
  Transmission Control Protocol
  → Stream index
  ```

  假设是 `3`，再过滤：

  ```
  tcp.stream eq 3
  ```

  最前面的三个包就是：

  ```
  SYN
  SYN, ACK
  ACK
  ```

- **TCP 客户端端口 / 服务端端口**
  点 TCP SYN 包，展开：

  ```
  Transmission Control Protocol
  ```

  看：

  ```
  Source Port
  Destination Port
  ```

  HTTPS 服务端一般是：

  ```
  Destination Port: 443
  ```

  客户端端口是一个随机高位端口。

- **TCP 三次握手耗时**
  看 Wireshark `Time` 列：

  ```
  SYN      1.230000
  SYN ACK  1.260000
  ACK      1.261000
  ```

  可以记录：

  ```
  SYN → SYN ACK ≈ 30 ms
  ```

  这个大致对应 RTT。课件说明 TCP 建连大约需要 1 RTT。

- **TLS / HTTPS 信息**
  过滤：

  ```
  tls
  ```

  找：

  ```
  Client Hello
  Server Hello
  Application Data
  ```

  点 `Client Hello` 或 `Server Hello`，展开：

  ```
  Transport Layer Security
  ```

  可以记录：

  ```
  TLS版本
  是否有Client Hello
  是否有Server Hello
  是否有Application Data
  ```

- **是否能看到 HTTP 明文**
  过滤：

  ```
  http
  ```

  如果没有包，记录：

  ```
  未观察到明文 HTTP
  ```

  因为访问的是 HTTPS，HTTP 内容被 TLS 加密。
  如果能看到重定向或明文请求，再记录实际情况。

- **wget 是否成功 / 是否重定向 / 文件大小**
  直接看 `wget` 终端输出：

  ```
  Resolving ...
  Connecting ...
  HTTP request sent ...
  200 OK
  301 / 302
  Length: ...
  Saving to ...
  ```

  记录：

  ```
  是否成功
  HTTP状态码
  是否重定向
  文件大小
  最终保存文件
  ```

- **协议封装层次**
  在 Wireshark 随便点一个 DNS 包，下面会看到：

  ```
  Ethernet II
  Internet Protocol
  User Datagram Protocol
  Domain Name System
  ```

  对应：

  ```
  Ethernet → IP → UDP → DNS
  ```

  再点一个 TLS/TCP 包，会看到：

  ```
  Ethernet II
  Internet Protocol
  Transmission Control Protocol
  Transport Layer Security
  ```

  课件要求观察的就是不同协议层次的封装关系。01-互联网体系结构初识.pptxPPTX

你最后可以直接整理成这个表：

| 要记录的数据              | 获取方式                             |
| ------------------------- | ------------------------------------ |
| h1 IP / MAC               | `h1 ip addr`                         |
| 默认网关                  | `h1 ip route`                        |
| DNS Server                | `cat /etc/resolv.conf`               |
| UCAS IP                   | Wireshark `dns` → Response → Answers |
| ARP 目标 IP / MAC         | Wireshark `arp`                      |
| DNS Query / Response      | Wireshark `dns`                      |
| TCP 三次握手              | `tcp.stream eq N`                    |
| 客户端/服务器端口         | TCP 包详情                           |
| TLS 信息                  | Wireshark `tls`                      |
| HTTP 是否明文可见         | Wireshark `http`                     |
| wget 状态/文件大小/重定向 | wget 终端输出                        |
| 协议封装层次              | Wireshark Packet Details             |
