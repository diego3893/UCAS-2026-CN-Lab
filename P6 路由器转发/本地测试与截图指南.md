# P6本地测试与截图指南

## 1 文件用途

- `06-router.tar.gz`和`06-router/`：课程原始附件与解压基线，保留原内容。
- `router/`：已实现的代码、本地拓扑和测试脚本。使用这里做实验。
- `router-submit.zip`：OJ提交包，只含根目录的Makefile、C源码和`include/`头文件。

以下代码块均可直接复制，没有`mininet>`或Shell提示符。分清“WSL终端”与“Mininet终端”，不要在Mininet里执行`sudo python3`。

## 2 启动WSL和安装依赖

在Windows终端打开Ubuntu，或者在PowerShell执行：

```powershell
wsl -d Ubuntu-24.04
```

进入WSL后，如果目录在Windows桌面，执行：

```bash
cd "/mnt/c/Users/30130/Desktop/CN_Lab/P6 路由器转发/router"
sudo apt-get update
sudo apt-get install -y build-essential mininet iproute2 iptables arptables ethtool tcpdump traceroute iputils-ping
```

如果你把整个CN_Lab复制在Linux家目录，进入目录的命令改为：

```bash
cd "$HOME/CN_Lab/P6 路由器转发/router"
```

后续命令都在该`router/`目录执行。不要把Windows路径直接粘贴进WSL。

## 3 一次运行全部本地检查

```bash

sudo python3 run_tests.py --extended
```

最后应显示`17/17 checks passed`。输出目录自动按当前时间命名；每次重新运行都会生成新目录，不覆盖原日志。脚本自动建立单路由器和三跳拓扑、配置静态路由、禁止内核代答/转发、启动用户态router、采集报文，并在结束时清理本次拓扑。ARP缓存老化检查会额外等待16秒。不要同时运行其他Mininet实验。

这是本地对公开功能的检查，不代表OJ隐藏测试已通过。需要看具体命令输出和抓包，不能只截最后一行。

## 4 手动运行单路由器拓扑并截图

### 4.1 编译和启动

在WSL终端执行，截取编译成功的最后几行，替换报告“图1”：

```bash
make clean
make
sudo python3 lab_topology.py --mode single
```

脚本已启动router，不要再执行`r1 ./router`，也不需要开xterm。Mininet退出前，接口只存在于各节点网络命名空间中，所以在普通WSL终端对`r1-eth0`直接抓包会提示设备不存在。

### 4.2 连通性

以下命令在Mininet输入，截图包含三组的统计行，替换“图2”：

```text
h1 ping -n -c 2 10.0.1.1
h1 ping -n -c 2 10.0.2.22
h1 ping -n -c 2 10.0.3.33
```

### 4.3 错误反馈

仍在同一个Mininet输入，替换“图3”。第一项需要等待约5秒，不要提前中断：

```text
h1 ping -n -c 1 -W 8 -w 9 10.0.3.11
h1 ping -n -c 1 -W 2 -w 3 10.0.4.1
h1 ping -n -c 1 -W 2 -w 3 -t 1 10.0.2.22
h1 ping -n -c 2 10.0.2.22
```

依次应出现`Destination Host Unreachable`、`Destination Net Unreachable`、`Time to live exceeded`，最后正常收到2个应答。未知主机时，Linux ping可能在收到首个错误前连续发出多份探测，因此即使`-c 1`，统计也可能显示发了多份；关注返回的ICMP错误类别，不要求它必须只发一个包。

### 4.4 手动抓ARP和ICMP

如需重新采集图4的证据，在Mininet中执行：

```text
r1 tcpdump -n -U -i r1-eth2 -w /tmp/p6-arp.pcap arp > /tmp/p6-arp-capture.log 2>&1 & echo $! > /tmp/p6-arp.pid
h1 tcpdump -n -U -i h1-eth0 -w /tmp/p6-icmp.pcap icmp > /tmp/p6-icmp-capture.log 2>&1 & echo $! > /tmp/p6-icmp.pid
sh sleep 1
h1 ping -n -c 1 -W 8 -w 9 10.0.3.11
sh sleep 2
r1 kill -INT $(cat /tmp/p6-arp.pid)
h1 kill -INT $(cat /tmp/p6-icmp.pid)
sh sleep 1
```

以上命令记录各自的抓包PID，只结束这两次抓包。已有自动测试PCAP可直接使用，无需重复这一步。

在WSL终端查看真实抓包：

```bash
sudo tcpdump -nn -tttt -r /tmp/p6-arp.pcap
sudo tcpdump -nn -vv -r /tmp/p6-icmp.pcap
```

或者直接读取自动测试产生的`single-r1-eth2.pcap`和`single-h1-eth0.pcap`。Wireshark打开PCAP后，ARP筛选条件是`arp.opcode == 1 && arp.dst.proto_ipv4 == 10.0.3.11`；ICMP错误筛选条件是`icmp.type == 3 || icmp.type == 11`。图4应能看见同一ARP请求约1秒间隔、共5次，以及ICMP的Type/Code和引用的原IP头、原ICMP头。

截图只保留相关命令和输出，或者Wireshark相关报文行与字段展开区。不要重新排版制造输出，也不要把旧实验截图拿来代替。

测试结束，在Mininet输入：

```text
exit
```

## 5 三跳拓扑并截图

退出上一个Mininet后，在WSL终端执行：

```bash
sudo python3 lab_topology.py --mode multi
```

在新Mininet中执行，前两项双向连通性替换“图5”，后续入口地址和traceroute替换“图6”，屏幕放不下可拆图：

```text
h1 ping -n -c 2 10.0.2.22
h2 ping -n -c 2 10.0.1.11
h1 ping -n -c 2 10.0.1.1
h1 ping -n -c 2 10.0.12.2
h1 ping -n -c 2 10.0.23.2
h1 traceroute -n -q 1 -w 2 -m 6 10.0.2.22
h1 traceroute -I -n -q 1 -w 2 -m 6 10.0.2.22
```

两种traceroute的地址顺序都应是`10.0.1.1 → 10.0.12.2 → 10.0.23.2 → 10.0.2.22`。普通traceroute用UDP探测，`-I`用ICMP回显探测。路由器返回的入口接口地址是ICMP源地址，并非原探测包的目的地址。

```text
exit
```
