## 2 图1：编译与全部验收

```bash
make clean

sudo python3 lab_test.py
```

截图保留成功链接 `nat` 的命令，以及三种模式的PASS、最后的 `16/16 checks passed`。自动脚本会依次完成SNAT、DNAT、串联，不要同时再启动其他Mininet。每次输出保存到新的 `test-results/run-时间/`，脚本结束即清理本次进程和拓扑。

## 4 图3：SNAT两侧抓包

退出Mininet后，Windows Wireshark打开本次 `report-snat/snat/n1-eth0.pcap` 和 `n1-eth1.pcap`。本轮输出目录路径由脚本打印；若在Linux家目录，可在WSL执行：

```bash
explorer.exe "$(wslpath -w "$(realpath ../test-results/report-snat/snat)")"
```

过滤首次握手：

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

分别截内外接口相同TCP序号的SYN，显示源IP/端口及目的IP/端口。内部源应为10.21.0.1或10.21.0.2，外部源应为159.226.39.43，两个并发客户端外部端口不同。临时端口以本轮实际结果为准。

再筛选回复，截外部目的159.226.39.43及内部恢复为10.21.0.1/10.21.0.2的对应报文。IP/TCP详情中的TTL和地址也可用于图6。

## 5 图4：DNAT两服务

WSL启动：

```bash
sudo python3 lab_test.py --mode dnat --interactive --output ../test-results/report-dnat
```

脚本先自动验证原始IP页面与文件。截图保留两条页面PASS、页面本机IP分别为10.21.0.1/10.21.0.2，以及两个不同文件的下载PASS和哈希。随后Mininet中可执行：

```text
h3 curl --noproxy '*' -f http://159.226.39.43:8000/payload.bin -o /tmp/p10-dnat1.bin
h3 curl --noproxy '*' -f http://159.226.39.43:8001/payload.bin -o /tmp/p10-dnat2.bin
h3 wc -c /tmp/p10-dnat1.bin /tmp/p10-dnat2.bin
h3 sha256sum /tmp/p10-dnat1.bin /tmp/p10-dnat2.bin
exit
```

打开 `report-dnat/dnat/` 内两份PCAP，同样筛选SYN。外部目的159.226.39.43:8000/8001，在内部应分别成为10.21.0.1:8000和10.21.0.2:8000。返回包的外部源端口应分别恢复为8000/8001。图4可拆为页面/文件一张、报文转换一张。

## 6 图5：串联NAT

WSL执行：

```bash
cat chain-snat.conf
cat chain-dnat.conf
sudo python3 lab_test.py --mode chain --interactive --output ../test-results/report-chain
```

截图保留两配置、课程页面My IP为10.22.0.2、Remote IP为192.0.2.1，以及文件下载PASS。Mininet中可补充：

```text
h1 curl --noproxy '*' -f http://192.0.2.2:8000/payload.bin -o /tmp/p10-chain.bin
h1 wc -c /tmp/p10-chain.bin
h1 sha256sum /tmp/p10-chain.bin
exit
```

打开 `report-chain/chain/` 的四份PCAP。n1-eth0是最初内侧、n1-eth1与n2-eth0是互联段、n2-eth1是最终内侧。对照同一SYN序号，截去程三段变化及回复反向转换。n2的内部接口是eth1，不能与n1的接口方向混用。
