显示过滤器输入：

```text
tcp.port == 10001
```

截图应展示源/目的IP、端口、标志位及Seq/Ack。可以在TCP首部字段上右键选择“应用为列”，并适当拉宽Info列。本轮已测每组7条：SYN、SYN|ACK、ACK、FIN|ACK、ACK、FIN|ACK、ACK。实际重测若ACK/FIN被系统合并，条数可能变化，应按新截图更新报告，不能为了凑7条删除报文。

建议启用“编辑→首选项→Protocols→TCP→Validate the TCP checksum if possible”；本地脚本也独立检查了IP/TCP校验和。Wireshark显示Unverified只代表未校验，不能直接解释为错误。重新运行临时端口和绝对序号会变化；报告使用x/y描述握手，不需要固定这些随机值。

## 4 图5：两端状态与TIME_WAIT回收

```bash
grep 'switch state' ../test-results/my-run/cc/server.stderr
grep 'switch state' ../test-results/my-run/cc/client.stderr
```

截取两条命令和输出，主动端应能看到SYN_SENT、ESTABLISHED、FIN_WAIT-1、FIN_WAIT-2、TIME_WAIT、CLOSED；被动端连接应能看到SYN_RECV、ESTABLISHED、CLOSE_WAIT、LAST_ACK、CLOSED。监听Socket的LISTEN到CLOSED是另一条状态记录，不是连接跳过了挥手。

## 5 图6：状态机补充测试

从tcp_stack目录执行：


截图保留四组PASS。合成测试覆盖合并FIN|ACK、重复FIN、同时关闭、定时扫描回收、RST、模序号比较及关闭监听时清理子连接。它不创建真实网络；TIME_WAIT在该测试中通过20次扫描模拟，而图5来自真实定时器运行。packed首部可能产生编译警告，不能写成“无任何警告”。

## 7 想在Mininet中手动检查

```bash
sudo python3 lab_test.py --mode cc --output ../test-results/interactive --interactive
```

脚本验证完成后进入Mininet，网络和C协议栈仍在；刚才的连接已经关闭，原C服务端只处理一个连接。可在Mininet逐条输入下面命令，新建一次连接。以下代码没有提示符前缀：

```text
h1 ./tcp_stack server 10002 > /tmp/p11-server.out 2>/tmp/p11-server.err &
h2 ./tcp_stack client 10.0.0.1 10002 > /tmp/p11-client.out 2>/tmp/p11-client.err &
sh sleep 9
h1 cat /tmp/p11-server.err
h2 cat /tmp/p11-client.err
exit
```

该次新启动的两个进程位于节点中，退出Mininet时会随节点清理。用于正文截图时优先使用第2节脚本保存的日志和PCAP，以免混用两次运行数据。
